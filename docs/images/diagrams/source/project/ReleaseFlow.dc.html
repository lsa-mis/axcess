How a desktop release ships

Merging app code to main publishes a preview release. Installed apps offer it on their next launch.

Axcess
1
Merge to main
With a change under:
src/desktop/pyproject.tomluv.lock
or the workflow file. A manual run also works.
2
Build both apps
desktop-build.yml
macOS (Apple Silicon) and Windows (x64) build in parallel, stamped 0.1.<run number>.
3
Publish job
Creates GitHub release desktop-v0.1.N, marked latest. Adds version-less download names. Keeps the 10 newest.
4
App checks on launch
The installed app asks GitHub for the latest release and offers a newer one.
Windows
“Update now”, download, then “Restart now”.
macOS
“Download” opens the new disk image.
Watch out
No tests gate the publish job.
Builds are not notarized: macOS is ad-hoc signed, Windows is unsigned.
Separate lane: the public site
A change under site/ is pushed to main
pages.yml
GitHub Pages workflow
Publishes the committed site/ HTML
It does not run build.py. Run make site and commit the HTML first.
