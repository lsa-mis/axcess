Coverage

What Axcess checks, and what it honestly can't

The Web Content Accessibility Guidelines (WCAG) 2.2 define 55 Level A and AA success criteria. Axcess contributes evidence to 29 of them today. Every one of the 55 is listed below, including the 26 a person must test by hand, with the steps to do it.

At a glance

1. Perceivable 20 of 20 criteria

Can everyone perceive the content? Text alternatives for images, captions, contrast, zoom, and layouts that reflow on small screens.

1.1.1 Non-text Content Level APartly automated

What Axcess does

axe flags missing alt on img / area / input[type=image] and unlabelled SVGs; the image-of-text VLM separately flags pictures that are really text.

What a person still checks

Whether the alt text that IS present is a meaningful equivalent — and the decorative-vs-informative call — needs a human.

Checks involved:Rule engine (axe-core)Image text check· Confidence: medium
1.2.1 Audio-only and Video-only (Prerecorded) Level AAI-assisted lead

What Axcess does

For <audio> elements, the semantic LLM checks whether a transcript or text alternative is reachable (nearby "Transcript" link / surrounding text).

What a person still checks

Confirm the transcript is accurate and equivalent. Video-only (silent video) can't be detected from the DOM — still a manual check.

Checks involved:Meaning check (local AI)· Confidence: medium
1.2.2 Captions (Prerecorded) Level AManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

Play each video and confirm synchronized, accurate captions. Auto-caption diffing (Whisper) is on the roadmap.

1.2.3 Audio Description or Media Alternative (Prerecorded) Level AManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

Confirm an audio description or full text alternative for prerecorded video.

1.2.4 Captions (Live) Level AAManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

Confirm live audio in synchronized media has real-time captions.

1.2.5 Audio Description (Prerecorded) Level AAManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

Confirm prerecorded video has a synchronized audio description track.

1.3.1 Info and Relationships Level APartly automated

What Axcess does

axe checks list, table-header, definition-list, required-ARIA-children and heading-structure markup on the rendered DOM.

What a person still checks

Relationships conveyed only visually (grouped fields, columns, emphasis that implies meaning) need a human to confirm they're also programmatic.

Checks involved:Rule engine (axe-core)· Confidence: medium
1.3.2 Meaningful Sequence Level AAI-assisted lead

What Axcess does

The visual probe screenshots the page and asks a local vision model whether the visual reading order matches the DOM/source order (CSS can reorder content so screen readers hear a different sequence).

What a person still checks

Confirm the model's call by tabbing/reading with a screen reader. Subtle reorderings and content below the fold still need a human, and the probe only runs when a local vision model is available.

Checks involved:Visual and motion check· Confidence: medium
1.3.3 Sensory Characteristics Level AManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

Read instructions for reliance on shape/size/location/sound alone ("click the round button to the right") — judgement only a human can make.

1.3.4 Orientation Level AAManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

Confirm content isn't locked to portrait or landscape (rotate the device / check for orientation-locking CSS).

1.3.5 Identify Input Purpose Level AAPartly automated

What Axcess does

axe validates that any autocomplete tokens used are valid.

What a person still checks

Confirm autocomplete IS present on fields collecting the user's own info (name, email, address) — missing autocomplete isn't auto-detected.

Checks involved:Rule engine (axe-core)· Confidence: medium
1.4.1 Use of Color Level APartly automated

What Axcess does

axe flags links distinguished from surrounding text by colour alone (a narrow heuristic).

What a person still checks

Most colour-only meaning — form errors, chart series, required-field markers, status — needs a human to confirm a non-colour cue exists.

Checks involved:Rule engine (axe-core)· Confidence: low
1.4.2 Audio Control Level APartly automated

What Axcess does

The visual probe measures actual playback advancement and flags audible audio longer than three seconds when no native or explicitly associated custom control is detected. Autoplay markup alone is not flagged.

What a person still checks

Confirm every audible autoplay source can be paused, stopped, or volume controlled independently; test custom controls and browser autoplay policy.

Checks involved:Visual and motion check· Confidence: medium
1.4.3 Contrast (Minimum) Level AAPartly automated

What Axcess does

axe measures text/background contrast on the rendered DOM against the 4.5:1 (3:1 large-text) thresholds.

What a person still checks

Text baked into images, hover/focus/disabled states, and text over gradients or photos need a human to check.

Checks involved:Rule engine (axe-core)· Confidence: medium
1.4.4 Resize Text Level AAAutomated

What Axcess does

The responsive probe zooms to a 200% proxy viewport and flags text that clips or overflows its container.

What a person still checks

Confirm no loss of content or function across the full zoom range in your target browsers.

Checks involved:Zoom and reflow check· Confidence: high
1.4.5 Images of Text Level AAAI-assisted lead

What Axcess does

OCR + a local vision model judge whether each image is really rendered text rather than a photo/diagram.

What a person still checks

Confirm flagged images aren't the allowed exceptions (logos, or text that's essential to a particular presentation).

Checks involved:Image text check· Confidence: medium
1.4.10 Reflow Level AAAutomated

What Axcess does

The responsive probe loads each page at 320 CSS px and flags horizontal scrolling / overflow.

What a person still checks

Confirm no content or functionality is lost in the reflowed view (some loss can pass the geometry check but still fail in use).

Checks involved:Zoom and reflow check· Confidence: high
1.4.11 Non-text Contrast Level AAManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

Check that UI component boundaries (inputs, buttons, focus rings) and meaningful graphics meet 3:1. No reliable automated rule exists yet.

1.4.12 Text Spacing Level AAAutomated

What Axcess does

The responsive probe injects the WCAG text-spacing override CSS (line-height 1.5, etc.) and flags clipping/overlap.

What a person still checks

Confirm no text is cut off or overlapping with the spacing applied.

Checks involved:Zoom and reflow check· Confidence: high
1.4.13 Content on Hover or Focus Level AAManual only

What Axcess does

What a person still checks

For tooltips/popovers triggered by hover/focus, confirm they're dismissable, hoverable, and persistent.

2. Operable 20 of 20 criteria

Can everyone operate the site? Keyboard access, enough time, nothing that flashes, and clear ways to navigate and find things.

2.1.1 Keyboard Level APartly automated

What Axcess does

axe flags some keyboard-inaccessible patterns; the keyboard probe confirms focus can move through the page.

What a person still checks

Confirm every control (menus, custom widgets, drag handles) is fully operable by keyboard — the deepest part of this SC is manual.

Checks involved:Rule engine (axe-core)Keyboard check· Confidence: medium
2.1.2 No Keyboard Trap Level APartly automated

What Axcess does

The keyboard probe emits a review lead only when the same observable element resists repeated Tab and Shift+Tab exit attempts. It suppresses normal focus wrapping, small focus cycles, modal containment, and opaque iframe or closed-shadow focus.

What a person still checks

Reproduce every lead and test components that appear after interaction. Confirm whether arrow keys, Escape, a close control, or a documented non-standard command lets the user leave before recording a failure.

Checks involved:Keyboard check· Confidence: medium
2.1.4 Character Key Shortcuts Level AManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

If single-character shortcuts exist, confirm they can be turned off, remapped, or are active only on focus.

2.2.1 Timing Adjustable Level AManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

For any time limit, confirm it can be turned off, adjusted, or extended.

2.2.2 Pause, Stop, Hide Level APartly automated

What Axcess does

The visual probe measures actual playback advancement for visible video longer than five seconds without a detected control. It also records <marquee> as an expert-review lead.

What a person still checks

CSS animations, auto-advancing carousels, and auto-updating regions aren't auto-detected — confirm any content that moves >5s can be paused, stopped, or hidden.

Checks involved:Visual and motion check· Confidence: medium
2.3.1 Three Flashes or Below Threshold Level AManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

Confirm nothing flashes more than three times per second. Flash analysis is not implemented.

2.4.1 Bypass Blocks Level APartly automated

What Axcess does

axe checks for a skip link, landmark regions, and a heading structure that lets users bypass repeated content.

What a person still checks

Confirm the skip link actually moves focus and works with the keyboard.

Checks involved:Rule engine (axe-core)· Confidence: medium
2.4.2 Page Titled Level AAutomated

What Axcess does

axe checks that every page has a non-empty <title>.

What a person still checks

Confirm the title is descriptive and distinguishes the page (a light human check).

Checks involved:Rule engine (axe-core)· Confidence: high
2.4.3 Focus Order Level APartly automated

What Axcess does

The focus probe flags positive tabindex (WCAG failure F44) — a manual tab order that overrides the natural DOM order and usually breaks the sequence.

What a person still checks

Tab through the whole page and confirm the focus order preserves meaning and operability — the order can break without a positive tabindex (e.g. CSS-reordered columns), which still needs a human.

Checks involved:Focus check· Confidence: medium
2.4.4 Link Purpose (In Context) Level AAI-assisted lead

What Axcess does

axe flags empty/unnamed links; the semantic LLM judges whether the link text plus its context conveys where it goes.

What a person still checks

Confirm the LLM's borderline calls ("read more", icon links) — it flags strong leads, not verdicts.

Checks involved:Rule engine (axe-core)Meaning check (local AI)· Confidence: medium
2.4.5 Multiple Ways Level AAManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

Confirm at least two ways to find pages (nav + search, or sitemap), except for steps in a process.

2.4.6 Headings and Labels Level AAAI-assisted lead

What Axcess does

axe flags empty headings / unlabelled controls; the semantic LLM judges whether each heading actually describes the content it introduces.

What a person still checks

Confirm the LLM's borderline heading calls, and check that form-control LABELS are descriptive — label descriptiveness is not yet AI-assisted.

Checks involved:Rule engine (axe-core)Meaning check (local AI)· Confidence: medium
2.4.7 Focus Visible Level AAPartly automated

What Axcess does

axe has limited checks for suppressed focus indicators.

What a person still checks

Tab the whole page and confirm a clearly visible focus indicator on every interactive element — largely manual.

Checks involved:Rule engine (axe-core)· Confidence: low
2.4.11 Focus Not Obscured (Minimum) Level AAPartly automated

What Axcess does

The live-page focus probe focuses each element and flags any whose centre is covered by a position:fixed/sticky overlay (the classic "focus hidden behind the sticky header" failure).

What a person still checks

Confirm partial-overlap cases the centre-point check can miss, and tab through interactively — overlays that appear only after a click still need a human.

Checks involved:Focus check· Confidence: medium
2.5.1 Pointer Gestures Level AManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

For any multipoint/path gesture (swipe, pinch), confirm a single-pointer alternative exists.

2.5.2 Pointer Cancellation Level AManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

Confirm actions fire on the up-event and can be aborted (no critical action on down-press).

2.5.3 Label in Name Level APartly automated

What Axcess does

axe flags controls whose accessible name doesn't contain the visible label text (label-content-name-mismatch).

What a person still checks

Confirm the visible text is fully contained in the accessible name for voice-control users.

Checks involved:Rule engine (axe-core)· Confidence: medium
2.5.4 Motion Actuation Level AManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

If a function is triggered by device motion (shake/tilt), confirm a UI alternative and a way to disable motion actuation.

2.5.7 Dragging Movements Level AAManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

For any drag operation (sliders, reorder, kanban), confirm a single-pointer alternative (tap/click) exists.

2.5.8 Target Size (Minimum) Level AAPartly automated

What Axcess does

axe checks interactive targets are at least 24x24 CSS px (with spacing).

What a person still checks

Confirm the inline / essential / equivalent-control exceptions are genuinely met for any flagged small targets.

Checks involved:Rule engine (axe-core)· Confidence: medium

3. Understandable 13 of 13 criteria

Can everyone understand it? Readable language, predictable behaviour, and forms that help people avoid and fix mistakes.

3.1.1 Language of Page Level AAutomated

What Axcess does

axe checks <html> has a present and valid lang attribute.

What a person still checks

Confirm the declared language actually matches the page's main content.

Checks involved:Rule engine (axe-core)· Confidence: high
3.1.2 Language of Parts Level AAPartly automated

What Axcess does

axe validates lang attributes that are present on parts of the page.

What a person still checks

Detecting foreign-language passages that are *missing* a lang attribute needs a human reader.

Checks involved:Rule engine (axe-core)· Confidence: low
3.2.1 On Focus Level AManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

Confirm moving focus to a control doesn't trigger an unexpected context change (auto-submit, new window).

3.2.2 On Input Level AManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

3.2.3 Consistent Navigation Level AAManual only

3.2.4 Consistent Identification Level AAManual only

What Axcess does

What a person still checks

3.2.6 Consistent Help Level AManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

3.3.1 Error Identification Level AManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

Submit forms with invalid data and confirm errors are identified in text. Requires interaction the crawler doesn't perform.

3.3.2 Labels or Instructions Level AAI-assisted lead

What Axcess does

axe checks a programmatic label exists; the semantic LLM judges whether each control's label/instructions are sufficient to know what to enter.

What a person still checks

Confirm the LLM's sufficiency calls, and test real form submissions — error-time instructions (SC 3.3.x) still need a human.

Checks involved:Rule engine (axe-core)Meaning check (local AI)· Confidence: medium
3.3.3 Error Suggestion Level AAManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

Trigger validation errors and confirm the page suggests how to fix them.

3.3.4 Error Prevention (Legal, Financial, Data) Level AAManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

For legal/financial/data submissions, confirm reversal, checking, or confirmation is available.

3.3.7 Redundant Entry Level AManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

In multi-step flows, confirm previously-entered info is auto-populated or selectable rather than re-typed.

3.3.8 Accessible Authentication (Minimum) Level AAManual only

What Axcess does

No automated check yet. The report includes this criterion in the manual testing list with the steps below.

What a person still checks

Manually test each in-scope sign-in and MFA step. Confirm it does not require a cognitive function test (for example, solving a puzzle or memorizing/transcribing information) without an accessible alternative. A successful post-MFA crawl only proves that an auditor established a temporary browser session; it does not automatically evaluate or pass the authentication experience. Do not record passwords, OTPs, passkeys, recovery codes, cookies, or session details in this report.

4. Robust 2 of 2 criteria

Does it work with assistive technology? Names, roles, and status messages that screen readers can rely on.

4.1.2 Name, Role, Value Level APartly automated

What Axcess does

axe checks names/roles/values for standard controls and ARIA widgets (button-name, link-name, aria-* validity, roles).

What a person still checks

Custom widgets' state changes (expanded, selected, checked) need a screen reader to confirm they're announced.

Checks involved:Rule engine (axe-core)· Confidence: medium
4.1.3 Status Messages Level AAPartly automated

What Axcess does

axe checks for some live-region / role=status markup.

What a person still checks

Confirm dynamic updates (added-to-cart, validation, search counts) are actually announced — needs screen-reader testing.

Checks involved:Rule engine (axe-core)· Confidence: low
